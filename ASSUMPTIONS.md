# Assumptions

1. **One Next.js full-stack project.** The project owner overrode the original monorepo/separate-API/static-web rules. Hono runs inside a Next.js route handler; Drizzle uses Neon.
2. **APK build.** The APK is a static export of the same project. `npm run build:mobile` temporarily moves `src/app/api` out of the app tree because a static export cannot contain server route handlers, builds with `NEXT_BUILD_TARGET=mobile`, then restores the route. Capacitor 8.6 bundles `out/` and calls the Vercel API baked in at build time via `NEXT_PUBLIC_API_URL`. It does not use `server.url`.
3. **Emergency pauses all active timers** on the affected bed. Only *planned* tier 3–4 tasks are auto-deferred. Active tier 3–4 tasks are paused and remain for the nurse. Tier 1–2 tasks are never deferred; they are flagged `needsAttention` while the emergency is active.
4. **Reschedule default:** the proposed planned window is the old window shifted by the actual emergency duration (both `plannedFrom` and `plannedTo`). A fixed-offset mode exists in config. No `TASK_RESCHEDULED` event is written until the nurse confirms or edits the proposal.
5. **Recurring tasks:** the next instance starts at `completion time + intervalMin` and ends at that start plus `expectedMin`. This guarantees a full interval after care is complete; the alternative (previous due + interval) would create instantly overdue work. One successor is created per completion.
6. **Shift end:** any still-open task becomes `missed` with reason `shift_end`; active segments are closed at the shift-end timestamp.
7. **Tick-only completion** (`planned → done`) is allowed with `durationRecorded=false` and contributes zero direct-care minutes.
8. **Pinning is local UI state**, not a clinical event. It is stored on the Dexie task projection and does not sync.
9. **Head-nurse screens are online-only** and show an explicit connection state. Nurse logging, timers, emergency handling and handover work offline.
10. **Offline login:** a previously authenticated nurse can continue logging while offline. Sync waits for a valid JWT; an expired token requires an online re-login.
11. **Survey identity:** staff `participant_code` is stored, never a patient identifier. SUS and raw TLX are the only instruments.
12. **Bed nicknames are free text.** The UI warns against patient names/identifiers and limits length, but rule-based validation cannot reliably detect a name. This remains a human-input risk and is listed in the evaluation.
13. **Demo content** (task templates, intervals, tiers) is illustrative and needs ICU clinical review.
14. **Charts:** the deployed bundle uses lightweight custom SVG/CSS charts instead of Recharts to keep the single-project build lean. The visual/interaction requirements remain.
15. **Tests:** domain tests run under Vitest (`28` passing). API tests run against a disposable local Postgres in Docker (`scripts/api-test.ts`, `42` checks). Playwright covers authentication, self-registration, role routing, the privacy screen and the unit-management/assignment path against the production web build. `scripts/flow-check.mjs` exercises the full nurse journey (emergency, reschedule, timer, quick add, handover, shift end) and writes screenshots; it is a verification script rather than an isolated test because it creates a real shift.
16. **Local Neon flakiness.** The Neon pooler occasionally returns `ENOTFOUND`/timeouts from this development network on a cold login. The app shows the offline/connection state and keeps nurse writes in Dexie; this is an environment limitation, not a domain rule.
17. **Deployment evidence.** The live deployment at <https://icu-tasklog.vercel.app> and GitHub Actions APK builds were observed. The task-edit release `e7cec95` and the null-ID fix `501b9af` deployed successfully; health, login, task-edit route and live head task-list checks passed against production. The APK from run `45031515210` was downloaded and inspected, including its bundled JavaScript. Installation/opening on a physical Android device remains **NOT VERIFIED** because no device or local Android SDK is available in this workspace.
18. **Mobile API URL.** The APK has no runtime server switcher. `NEXT_PUBLIC_API_URL` is compiled in, so the APK must be rebuilt if the Vercel URL changes.
19. **Nurse self-registration.** The public signup form creates nurse accounts only; the server never trusts a client-supplied role. Head-nurse accounts remain provisioned by the study team. Registration requires connectivity, has no email verification or PIN recovery, and is open to anyone who can reach the deployment. This is acceptable for the thesis demo but would need an invite code, rate limiting and recovery before real use.
20. **Planned windows and legacy events.** Task timing moved from a single `dueAt` to `plannedFrom`/`plannedTo`. Old events that still contain `dueAt` are normalized when read: `plannedTo = dueAt` and `plannedFrom = dueAt - expectedMin`. New production demo data was regenerated after the migration.
21. **Dynamic units are implemented.** A nurse can belong to multiple units; each shift belongs to exactly one unit; tasks inherit the shift unit. Any head nurse can manage all units in this thesis demo, with `created_by` retained for audit. Unit management is online-only; the nurse's assigned active units are cached for offline shift start. Archiving removes a unit from online shift choices and preserves historical shifts; queued offline shifts still sync if the unit exists, so work is not lost.
22. **Legacy shifts stay unassigned.** Shifts created before the unit migration keep `unit_id = NULL` and remain visible under “Unassigned” in the head-nurse filters. The server accepts an offline shift if the unit still exists even when the nurse assignment changed after the cached start, protecting queued offline work.
23. **Audited task alteration.** “Every user can alter the task” is implemented within the two-role boundary. A nurse can edit title, tier, category, planned window, expected minutes and note on unfinished tasks in the nurse’s own shift. A head nurse can do the same on any shift detail, including open shifts. Every change appends a `TASK_EDITED` event instead of rewriting prior events. Completed and missed tasks are frozen. The head nurse still cannot start, pause, complete, miss, defer or reschedule tasks, log interruptions or finalize handovers. If a nurse and head nurse edit the same task concurrently, the reducer applies events in timestamp order; the latest event wins. There is no three-way merge in this demo.
